# Guida agli asset

Le immagini definitive non sono ancora state approvate. Questa convenzione prepara gli slot senza aggiungere file fittizi. Creare le cartelle sotto `public/assets/` solo quando si dispone degli asset; Vite copia i file in `dist/assets/` senza elaborarli. Usare nomi minuscoli, trattini e identificativi stabili. I percorsi nel manifest iniziano con `/assets/` e distinguono maiuscole e minuscole.

| Tipo | Posizione e nome suggerito | Formato e dimensioni orientative | Associazione e sostituzione |
|---|---|---|---|
| Logo | `public/assets/brand/logo.webp` | WebP o PNG trasparente, circa 512 × 512 px; forma quadrata o con margini | Impostare `logo` in `src/content/assets.ts` a `/assets/brand/logo.webp`. L'app lo contiene in 43 × 43 px; il marchio testuale torna se manca o fallisce. Per sostituirlo, sovrascrivere il file o cambiare percorso nel manifest. |
| Icona sacchetto | `public/assets/brand/sacchetto.webp` | WebP o PNG trasparente, circa 256 × 256 px | Impostare `sackIcon` nel manifest a `/assets/brand/sacchetto.webp`. Il pulsante mantiene la sua etichetta accessibile; se l'immagine manca o fallisce usa un simbolo generico. Sostituire file o percorso. |
| Illustrazione del calendario | `public/assets/ui/24train.png` | PNG trasparente oppure WebP ottimizzato, formato orizzontale | Il manifest la collega tramite `calendarIllustration`; per sostituirla aggiornare il file o il percorso. Se manca, il calendario rimane utilizzabile. |
| Favicon | `public/assets/brand/favicon.png` | PNG 32 × 32 o 64 × 64 px, oppure ICO | Impostare `favicon` nel manifest a `/assets/brand/favicon.png`. Se non impostata o se fallisce, si usa un'icona vuota; per sostituirla cambiare file o percorso e ricostruire. Alcuni browser conservano la vecchia icona in cache. |
| Sfondo calendario e diario | `public/assets/backgrounds/calendario.webp`, `diario.webp` | WebP, circa 2048 × 1536 px; comprimere e verificare il ritaglio | Impostare `calendar` o `diary` nel manifest. Per cambiare l'immagine, sostituire il file o il percorso. |
| Illustrazione di una pagina del diario | `public/assets/days/day-01/diario.webp` | WebP o PNG, circa 800 × 800 px | Impostare `diaryIllustrations: { 1: { src: '/assets/days/day-01/diario.webp', alt: 'descrizione dell’immagine' } }` nel manifest. Appare solo nella voce acquisita; se manca o non si carica, la narrazione resta visibile. Sostituire file o percorso. |
| Sfondi capitoli | `public/assets/backgrounds/capitolo-01.webp` … `capitolo-06.webp` | WebP, circa 2048 × 1536 px; soggetto centrale leggibile anche con ritaglio | Impostare `chapters: { 1: '/assets/backgrounds/capitolo-01.webp' }`. Le sei fasce di quattro giorni sono provvisorie come in `05-STORY.md`; sostituire file o percorso quando approvato. |
| Sfondo di una giornata | `public/assets/backgrounds/giorno-01.webp` | WebP, circa 2048 × 1536 px | Impostare `days: { 1: '/assets/backgrounds/giorno-01.webp' }`. Lo sfondo del giorno prevale su quello del capitolo; rimuovere la voce per tornare al capitolo. Sostituire file o percorso per aggiornarlo. |
| Documenti e illustrazioni leggibili | `public/assets/documents/giorno-01/lettera.webp`, `biglietto.webp` | WebP o PNG, circa 1600–2400 px sul lato lungo, testo nitido e leggibile a zoom | Per il documento con ID `lettera`, impostare `documents: { 1: { lettera: '/assets/documents/giorno-01/lettera.webp' } }`. L'ID deve corrispondere al documento della giornata in `src/content/days.ts`; mantenere `text` come trascrizione accessibile e `imageAlt` descrittivo. Il manifest prevale sull'eventuale `image` del documento. Sostituire file o voce senza cambiare i componenti. |
| Oggetti, sagoma e immagine rivelata | `public/assets/items/<id>-sagoma.webp`, `public/assets/items/<id>.webp` | WebP o PNG trasparente, circa 512 × 512 o 1024 × 1024 px | Per un oggetto con ID `esempio`, impostare `items: { esempio: { silhouette: '/assets/items/esempio-sagoma.webp', image: '/assets/items/esempio.webp' } }`. Creare l'oggetto nel registro solo quando il contenuto è approvato. Il manifest prevale sui campi del registro. Sostituire file o percorso; l'oggetto usato viene desaturato via CSS, senza un terzo file. |

Le voci non impostate sono `null` o assenti: gli sfondi usano il fondo CSS, il logo e gli oggetti usano segnaposto generici, mentre un documento conserva la trascrizione anche se l'immagine manca. Gli sfondi sono decorativi e separati dai documenti; non inserirvi indizi indispensabili. Un velo scuro sopra le immagini protegge la leggibilità, ma verificare sempre contrasto, ritaglio e testo su iPad sia in orizzontale sia in verticale. Ottimizzare i file prima di inserirli e non caricare elementi non approvati: i file statici pubblicati sono accessibili anche se una giornata è bloccata.

Dopo ogni sostituzione eseguire `npm run lint`, `npm run typecheck`, `npm run test` e `npm run build`, quindi verificare anche la build su Safari. La semplice presenza di un'immagine non rende pronta o giocabile una giornata.

L'icona attualmente fornita è `public/assets/ui/sack.png`, collegata tramite `sackIcon`; il percorso `brand/sacchetto.webp` nella tabella è un'alternativa per una futura sostituzione.
